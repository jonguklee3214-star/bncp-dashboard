# BNCP 통합관리 대시보드 v2.3.0

화면이 둘로 나뉜다.

| 화면 | 누가 | 무엇을 |
|---|---|---|
| `vendor.html` | 협력업체 | **입력만** — 실적·인원장비·검측신청·측량신청·자재신청 |
| `index.html` | 우리 스탭·관리자 | 확인·승인·지급·집계·공정표 (입력 폼 없음) |

두 화면은 같은 저장소(localStorage `bncp.dash.v2`)를 쓴다. 협력업체가 넣으면 관리자 화면에 바로 올라온다.

## 1. 올리고 켜기

```bash
git init && git add -A && git commit -m "BNCP v2.3.0"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```
Settings → Pages → Deploy from a branch → **main / (root)**

- 관리자: `https://<계정>.github.io/<저장소>/`
- 협력업체: `https://<계정>.github.io/<저장소>/vendor.html`

협력업체에는 `vendor.html` 주소만 주면 된다. 관리 화면은 링크가 없으면 들어올 일이 없다.
로컬 확인은 `python3 -m http.server 8080`.

## 1-B. Vercel로 옮기기 (v2.53.0)

저장소에 `vercel.json`이 들어 있다 — 빌드는 없고, 캐시 머리말만 정해 준다
(`/assets/*`는 1년 고정, `.html`은 매번 새로 확인 → 새 판이 바로 뜬다).

**사용자가 할 일**

1. [vercel.com](https://vercel.com) 로그인 → **Add New… → Project** →
   이 GitHub 저장소를 고른다.
2. **Framework Preset = Other**, Build Command·Output Directory는 **비워 둔다**
   (정적 파일 그대로 올린다).
3. Deploy를 누르면 끝. 주소는
   - 관리자 : `https://<프로젝트>.vercel.app/`
   - 협력업체 : `https://<프로젝트>.vercel.app/vendor.html`

★**주소가 바뀌면 기기마다 저장된 것(`localStorage`)이 초기화된다.** 로그인·역할·
화면 설정이 비고, 기준자료는 서버에서 다시 내려받는다. 현장에 나가 있는 사람들의
북마크도 새 주소로 바꿔 줘야 한다.

## 1-C. 구글 계정 바꾸기 (시트·Apps Script)

1. **새 계정**에서 구글 스프레드시트를 하나 만든다(빈 시트여도 된다 — 필요한 시트는
   `Code.gs`가 알아서 만든다).
2. 확장 프로그램 → **Apps Script** → 저장소의 `Code.gs` 내용을 **통째로 붙여넣기**.
3. **배포 → 새 배포 → 웹 앱**
   - 실행 사용자 : **나**
   - 액세스 권한 : **모든 사용자**
   → 나오는 `.../exec` 주소를 복사한다.
4. 그 주소를 **`assets/js/api.js`의 `url:` 한 줄**에 넣는다. **주소가 적힌 곳은
   저장소를 통틀어 거기 한 곳뿐이다.**

★옛 계정의 시트는 그대로 둬도 된다 — 새 주소로 바꾸는 순간 아무도 그쪽을 부르지
않는다. 자료를 옮기려면 시트를 통째로 복사해 새 계정으로 옮기면 된다.

## 2. 협력업체 화면 (vendor.html)

라벨은 **English / العربية 병기**. 위치(Phase·Town·Block)와 장비명은 항상 영문.
진행률·승인·증감·공정표·생산성·지급대조 — **하나도 안 보인다.**

상단에서 위치를 고르고(부지: Phase→Section / 부대: Town→Block), 5개 탭 중 하나에 입력한다.

| 탭 | 입력 | 저장 상태 |
|---|---|---|
| Output | 공종 → 수량 | `제출` — 스탭 확인 전엔 진행률에 안 들어감 |
| Manpower & Equipment | 조수 · 엔지니어/포맨/워커 다이얼 · 장비(가동/고장/수리) | `제출` |
| Inspection | 공종 → 수량 | `신청` — **같은 날 실적이 없으면 신청 불가** |
| Survey | 공종 → 사유(TBM·CP점 등) | `미처리` |
| Material request | 대분류 → 세부공종 → 자재 → 수량 | `신청` — 스탭 승인 대기 |

- **장비기사는 입력하지 않는다.** 장비 가동 대수 = 기사 수(1:1)로 자동 계산되어 표시된다.
- 화면 아래에 "오늘 넣은 것"이 나와 중복 입력을 막는다.

## 3. 관리자 화면 (index.html) — 6개 탭

| 탭 | 하는 일 |
|---|---|
| **작업현황** | 올라온 실적·인원장비 확인 처리 → 진행률·실측 생산성·공종별 집계·장비 지급대조 |
| **검측** | 신청 → **스탭 완료확인** → 제출 → 합격/불합격/검측지연. 불합격·지연은 사유 필수, 재검측 생성 |
| **측량** | 처리/미처리 전환 |
| **자재현황** | 설계수량 시트 업로드 → 승인/미승인 → 지급/미지급(사유) → 증감. 창고/플랜트 분리 |
| **알림·전파** | 걸린 것 모아 문구 자동작성 · 발송 이력(테스트 모드) |
| **공정표** | 진행률에서 파생, 인쇄 |

언어: 한국어 · English · বাংলা (아랍어는 협력업체 화면 전용)

### 자재 워크플로
```
[창고 자재]
  협력업체 신청 → 스탭 승인/미승인(사유) → 지급/미지급(사유) → 설계 대비 증감

[플랜트 지급자재]  레미콘·아스콘·모래·경계석·보조기층 등 27종
```

## 8. 계산 규칙

- **진행률** = 확인된 누적 실적 ÷ 설계목표
- **평균 진행률** = 설계목표가 있는 공종의 진행률 산술평균(100% 상한). 단위가 섞여 물량 가중 불가
- **실측 생산성(조당 1일)** = Σ확인수량 ÷ Σ조수. 날짜·위치·공종이 같은 인원장비 기록과 짝지어진 것만
- **장비기사** = 가동 대수(1:1). 고장·수리 장비는 기사 미배치로 본다
- **소요일** = 설계목표 ÷ 조당 생산성 (`ceil`). 실측 우선, 없으면 기준값
- **자재 증감** = 지급 − 설계 (플랜트는 실사용 − 설계도 함께)
- **장기 기준** = 장비 고장·수리 2일. 검측·측량에는 장기 개념 없음

## 9. 언어

화면 라벨은 한국어 · English · বাংলা 3개 언어가 사전(`assets/js/i18n.js`, 318키)에 다 들어 있다.
코드에 한국어를 직접 쓰지 말고 `T('key')`를 쓴다. 키가 늘면 `tools/i18n_map.py`에 적고 돌린다.

**공종명 975개 · 자재명 296개는 사전이 없어** EN/BN에서도 한국어 원문으로 나온다(층3).
`node tools/smoke.js`의 [17] 언어 순수성 검사가 UI 라벨에 한국어가 남았는지 잡아내며,
층3 원문과 사용자 입력은 검사에서 제외한다.

아랍어는 협력업체 화면(`vendor.html`) 라벨 병기 전용이다.
